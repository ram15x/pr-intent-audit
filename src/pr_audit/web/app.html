How it works

A requirement-by-requirement check, with evidence you can verify.

1. Split

The ask is split into requirements by rules, not a model. Checklists work best; free-form prose gives weaker splits.

2. Retrieve

Word-overlap ranking finds the diff hunks that could address each requirement (a trained model is optional).

3. Judge

A free-tier LLM reads the top hunks and answers done / partial / missing / unclear, citing hunks and quoting lines.

4. Verify

Plain code checks every cited hunk and quote really exists in the diff. Anything unverifiable becomes "unclear".

What to keep in mind

It reads diffs, not behaviour

"Done" means the diff plausibly implements it. It does not run your code or tests.

Measured on a small, single-annotator set

The labels behind the published numbers are not independently reviewed. See docs/RESULTS.md for the figures and their intervals.

Free-tier quota

Groq's free plan allows about 200K tokens a day. One audit is typically a few thousand. Cached answers are reused.

Privacy
